# MCP Server

Use the hosted Genfeed MCP server to give your agent permission-scoped access to content, workflows, publishing, analytics, and ads.

**Endpoint:** `https://mcp.genfeed.ai/mcp`

**Transport:** Streamable HTTP.

**Default authentication:** browser OAuth; no manually created API key.

Open the [guided Connect Genfeed flow](https://app.genfeed.ai/connect) to choose
your client and authorize access. The page supplies setup instructions; your
client owns sign-in, consent, and the resulting access token.

## Connect via OAuth

Add Genfeed using the instructions below, complete sign-in and consent in your
browser, and return to your client. Genfeed advertises its authorization server
through `/.well-known/oauth-protected-resource`.

### Claude Code

```bash
claude mcp add --transport http genfeed --scope user https://mcp.genfeed.ai/mcp
```

Open `/mcp` inside Claude Code, select `genfeed`, and authenticate. Follow the
browser sign-in and consent flow, then return to Claude Code.

### Codex

```bash
codex mcp add genfeed --url https://mcp.genfeed.ai/mcp
```

If authorization did not open during setup, run:

```bash
codex mcp login genfeed
```

Alternatively, add this to your user-level `~/.codex/config.toml` and run the
login command above:

```toml
[mcp_servers.genfeed]
url = "https://mcp.genfeed.ai/mcp"
```

### Other MCP clients

In a client that supports remote Streamable HTTP and OAuth, add the endpoint as
a custom MCP server and follow its browser authorization flow. Installation and
availability depend on the client and your plan. If OAuth is unsupported, update
your client or use the advanced manual-key setup below. No application deep link
is required.

Genfeed uses standard discovery, registration, and PKCE flows. Clients that
implement these protocols are expected to be compatible, but each client still
needs a recorded verification run. Source compatibility does not establish that
its OAuth, reconnect, or media flows work in a deployed client.

### Authorization server conformance

What a spec-compliant client can rely on:

- **Discovery (RFC 9728).** Protected-resource metadata is served at both
  `https://mcp.genfeed.ai/.well-known/oauth-protected-resource` and the
  path-suffixed `https://mcp.genfeed.ai/.well-known/oauth-protected-resource/mcp`
  with identical bodies. A `401` from `/mcp` carries a `WWW-Authenticate` header
  pointing at that metadata. Authorization-server metadata is at
  `https://api.genfeed.ai/.well-known/oauth-authorization-server`. Both
  documents are readable cross-origin.
- **Resource identifier (RFC 8707).** The `resource` is always
  `https://mcp.genfeed.ai/mcp`. Send it on the authorize and token requests.
- **Registration (RFC 7591).** `POST /v1/oauth/register` with `redirect_uris`;
  `token_endpoint_auth_method` is `none`.
- **Authorization.** `code_challenge_method` must be `S256`. `state` is
  optional; when supplied it is echoed unchanged on both the success and the
  `access_denied` redirect.
- **Tokens.** The token exchange returns an access token and a
  `refresh_token`. Access tokens expire after 30 days. Present the refresh
  token with `grant_type=refresh_token` to obtain a new access token without a
  second consent screen; each refresh rotates the refresh token, and reuse of a
  consumed refresh token revokes the whole chain. A narrower `scope` may be
  requested on refresh; a wider one is rejected.
- **Revocation (RFC 7009).** `POST /v1/oauth/revoke` with the refresh token
  ends the connection. Revoking the key from Genfeed's API key settings has the
  same effect.

### Verify access

Ask your agent: **“List my Genfeed brands.”** A successful scoped read verifies
access. `codex mcp list` or `claude mcp list` can diagnose configuration, but a
server entry or copied command alone does not prove authorization. The Genfeed
setup page cannot observe a third-party client's OAuth completion.

If consent is denied or the login expires, restart authorization through
`codex mcp login genfeed` or Claude Code's `/mcp`. Check the account and organization
on the consent screen. Revoke unwanted access from Genfeed's API key settings.

Client syntax was checked against Codex CLI 0.153.2 (`mcp add --help` and
`mcp login --help`) and the [Claude Code MCP documentation](https://code.claude.com/docs/en/mcp).

## Advanced: manual API key

Use this for headless environments or clients without browser OAuth. Select
**Advanced: manual API key** in [Connect Genfeed](https://app.genfeed.ai/connect)
to create or select a scoped key and run the authenticated verification check.
Keys remain copy-once. See [API Keys](/api-reference/api-keys) for rotation and revocation.

In a Bash terminal where your client runs, enter the key without putting its
value in shell history:

```bash
read -s GENFEED_API_KEY && export GENFEED_API_KEY
```

Then choose your client:

```bash
claude mcp add --transport http genfeed --scope user https://mcp.genfeed.ai/mcp --header "Authorization: Bearer $GENFEED_API_KEY"
```

```bash
codex mcp add genfeed --url https://mcp.genfeed.ai/mcp --bearer-token-env-var GENFEED_API_KEY
```

The Claude command expands the key into client configuration; protect that local
configuration. Codex reads the named environment variable. Do not paste credentials
into chats, commits, or shared logs. Inspect and update an existing Genfeed server
entry before switching authentication methods; preserve unrelated servers.

## Social accounts, brand scope, and media

Use `list_brands` then pass `brandId` into generation and connection tools. Genfeed
does not silently pick the first organization brand.

`connect_social_account` returns a `connectionId` and a browser authorization URL.
Poll `get_connection_status` with that id. Provider denial or failure is stored
on that row immediately (`denied` / `failed`); do not wait for the 15-minute
expiry. Replay the same id after a client restart; it does not create another
credential.

`generate_image` returns structured artifact metadata plus a native image part when
the client supports it, with a text fallback. Video results are downloadable files
or open links — they do not claim inline playback. `selectedContext` is task-only
and is not saved as Knowledge.

The CLI equivalents are `gf connect <platform>`, `gf gen image --brand --context`,
and `gf status <id>`. Client evidence lives in the repository file
`docs/external-agent-content-journey.md`.

## Publishing readiness

Before scheduling, call `list_scheduler_capabilities` and
`list_brand_publishing_readiness` for the selected brand. A connected account
alone does not make its channel schedulable. Readiness combines credential
health with the canonical scheduler capability catalog.

A `supported` channel retains its credential and setup checks. A `hidden`
channel has a backend integration but cannot be scheduled until live publishing
is verified; a `planned` channel has no available scheduling path. Both return
`canSchedule: false`, `state: "blocked"`, and a
`scheduler_channel_unavailable` diagnostic. Uncatalogued channels also fail
closed. Existing token, permission, and setup diagnostics remain available.

Facebook remains hidden. Reconnecting a healthy Facebook account does not enable
scheduling; choose a supported channel. This is a product capability restriction,
not evidence that the provider has banned the account.

## Tool errors

A gating failure is a tool result with `isError: true`. `structuredContent`
is the contract below — not a generic 500 and not a bare string. The same
object is `error.data` on the JSON-RPC response when the Streamable HTTP
transport rejects the request before a tool runs (missing credential, or the
shared `RateLimitService` window). JSON-RPC `error.code` stays numeric.

| `code` | When | `nextStepUrl` | Extra fields |
| --- | --- | --- | --- |
| `unauthorized` | Missing or rejected bearer credential (`401`) | `/connect` on the app origin — the same Connect Genfeed sign-in the server already advertises | |
| `plan_required` | Paid-plan, subscription, plan-limit, or organization-billing gate (`hasOrganizationBilling()`, `PLAN_LIMIT_EXCEEDED`) | `/settings/subscription` | |
| `insufficient_credits` | Ledger rejection (`INSUFFICIENT_CREDITS`, HTTP 402) | `/settings/credits` | |
| `rate_limited` | `RateLimitService`, or an upstream `429` | none | `retryAfterSeconds` when the limiter reported a wait |
| `validation_failed` | REST `ValidationPipe` / `ErrorResponse.validationFailed` field errors, or a missing required tool argument | none | `errors[]` of `{ field, message }` |
| `approval_pending` | `mutationPolicy: 'approval-required'` queued the write instead of running it | `/publishing/review` | |

`message` is always set. `retryAfterSeconds` and `nextStepUrl` are omitted
when they do not apply — `rate_limited` does not invent a URL. Paths are the
app routes the product already uses; sign-in continues into the caller's
organization. Fix `errors[]` and call the tool again. For
`approval_pending`, hand the human `nextStepUrl` or call `resolve_approval`
with the approval id in `message`.

## Tools

Each call uses the permissions on the authorized token or manual key.

- **Content and media:** articles, images, videos, music, avatars, batches.
- **Workflows:** list, create, execute, inspect status.
- **Publishing:** list and publish social posts.
- **Analytics and ads:** analytics, campaigns, Google Ads, Meta Ads.
- **Agents and admin:** threads, approvals, role-gated admin tools.

## Toolsets

The bare endpoint uses the `default` profile. Profiles shape the advertised
`tools/list` selection:

| Endpoint selector | Advertised toolsets |
| --- | --- |
| No selector or `?profile=default` | `core`, `scheduler`, and `content`, capped at 31 tools. |
| `?profile=directory` | The same bounded selection, with `generation`, `clips`, and `ui` excluded. This profile does not imply directory approval. |
| `?profile=full` | All toolsets, subject to the caller's permissions. |

To expose the available content journey, including generation and analytics,
select these toolsets explicitly:

```text
https://mcp.genfeed.ai/mcp?toolsets=content,generation,analytics,brand,scheduler
```

- **`core` is always included** and cannot be excluded. It holds discovery and
  account/status tools.
- **A nonempty `toolsets` selection wins over `profile`.** Use comma-separated,
  kebab-case toolset names.
- **Absent or blank `toolsets` uses the selected profile**, or `default` when
  no profile is supplied. For example, `?toolsets=&profile=full` selects all
  toolsets; `?toolsets=` alone uses `default`.
- **Unknown toolset names, or an unknown profile when profile selection applies,
  return HTTP 400** before authentication, including public discovery requests.
- **`tools/call` permissions are unchanged.** A tool outside the advertised
  selection can still be called directly by name if the token permits it.
  Discovery selectors do not grant authorization or bypass approval checks.

### Saved remix handoff

Imported-post remix is not on the bare MCP URL. Reconnect with an explicit
profile so discovery includes the inspiration, content, generation, analytics,
brand, and scheduler toolsets:

```text
https://mcp.genfeed.ai/mcp?toolsets=inspiration,content,generation,analytics,brand,scheduler
```

`core` is still added automatically. The bare default profile and its tool cap
stay unchanged. Omitting `toolsets` still lists every tool.

Call the actions in this order. Saving, importing, reading, editing, attaching,
and quoting never dispatch generation, publish, or add brand Knowledge.

1. `import_source_post` — public X, Instagram, or TikTok URL plus explicit
   `brandId`. Approval is required. Unsupported, private, or missing inputs fail
   closed. The result is the imported source identity and whether it was reused.
2. `create_remix_concept` — `brandId` and `sourcePostId`. Creates or reuses the
   canonical saved concept and returns its current revision.
3. `update_remix_concept` — `runId`, `expectedRevision`, and at least one edit.
   A stale revision fails instead of overwriting.
4. `attach_remix_analysis_source` — optional, for video or avatar output.
   Pass a same-brand Library video id, or `null` to clear it. The Library video
   is the analyzed media. The imported post URL, author, and selector stay
   provenance. Attachment does not spend credits.
5. `quote_remix_generation` — persists an exact quote for `expectedRevision`
   and does not start work. Read it back with `get_remix_run` before approval.
   Image and copy accept only `operation: "generate"` and reject scene or repair
   fields. Image requires `model`. Copy ignores caller models and uses the
   canonical background model at one credit per variant. Video and avatar reject
   `model` and quote `analysis`, `generate`, or `repair` on the scene pipeline.
   A quote expires 15 minutes after it is saved. Price, model, BYOK, source, or
   recipe changes require a new quote.
6. `start_remix_generation` — approval-required. Pass the persisted `quoteId`
   and the same revision. A repeated accepted call returns the same canonical
   run and does not buy the attempt again.
7. `get_remix_run` — safe reconnect. Returns revision, lineage, quotes, receipts,
   and artifacts without starting another run.
8. `control_remix_generation` — approval-required `cancel` or `resume` for an
   existing video or avatar scene pipeline. Image and copy have no control
   action.

Image and copy execute through the generic generation quote. Video and avatar
execute through the scene pipeline. Single-scene legacy video or avatar start
is not an unquoted shortcut. Live native-client acceptance, paid provider
calls, and real publishing are not claimed here.

### Discover tools outside your selection

Three read-only meta tools, always in `core`, let an agent find a tool that
isn't in its current selection:

- **`list_toolsets`** — every toolset available on this server, with tool
  counts.
- **`search_tools`** — case-insensitive substring search over tool name,
  description, and toolset (`{ query?, toolset?, limit? }`, at least one of
  `query`/`toolset` required).
- **`describe_tool`** — the full tool definition for one name (`{ name }`),
  including the closest name matches when the name isn't found.

These search the full, role-filtered catalog regardless of the caller's
current toolset selection. Once an agent has a tool's name and schema from
`describe_tool`, it can call that tool directly with `tools/call` — narrowing
`tools/list` only narrows discovery, not what can be invoked — or reconnect
with a broader `?toolsets=` selection so the tool appears in future
`tools/list` responses.

## HTTP Details

The endpoint accepts `POST`, `GET`, and `DELETE`. Authenticated requests include a token managed by the OAuth client or a manual key:

```http
Authorization: Bearer <access-token>
```

Missing, invalid, or expired tokens return 401 errors. An OAuth client should
use its refresh token on a 401 before restarting browser authorization.

## Local Self-Hosted Surface

Self-hosted Genfeed uses `http://localhost:3014/mcp` when the MCP service is running. Cloud uses:

```text
https://mcp.genfeed.ai/mcp
```

## Troubleshooting

- **Discovery fails:** use exactly `https://mcp.genfeed.ai/mcp` and a Streamable HTTP client.
- **401 errors:** an OAuth client should present its refresh token first and
  restart browser authorization only if that fails; in manual mode, check the
  key and its scopes.
- **Wrong endpoint:** check `/v1/config` on the MCP host.

## Uploading local media

The default MCP profile includes `request_media_upload`, `complete_media_upload`,
and `get_post`. Select a brand before reserving an upload.

1. Call `request_media_upload` with `filename`, `contentType`, and `category`.
2. Upload to the returned `uploadUrl` before it expires. For `method: PUT`, send
   the file bytes with the returned headers. For self-hosted `method: POST_JSON`,
   send the returned `localUpload` object as JSON, adding the base64-encoded file
   bytes as `localUpload.source.data`. Respect the returned file constraints.
3. Call `complete_media_upload` with the returned `assetId`. Its `media` entries
   can be passed to `create_scheduled_release`; a returned hosted `url` can also
   be used in `create_post` `mediaUrls`. Scheduling retains its approval checks.
4. Use `get_post` with `postId` to read a post's targets, state, media, and timestamps.

Upload reservation creates a pending asset. Both upload tools are non-destructive
writes; `get_post` is read-only. None of these tools publishes a post.

## Interactive content cards

MCP Apps hosts can render Genfeed posts, articles, image galleries, video and audio
previews, generation results, and usage summaries directly in the conversation.
The MCP server serves a self-contained HTML resource at
`ui://genfeed/content-cards-v1.html` with MIME type
`text/html;profile=mcp-app`. Selected tool descriptors link it through
`_meta.ui.resourceUri`; the widget uses the standard MCP Apps JSON-RPC bridge.
No separate ChatGPT frontend deployment is needed.

Text and media resource links remain available to clients without MCP Apps.
Empty results and tool errors remain visible, and pending approvals are never
presented as completed content. Cards do not publish or mutate content.

For self-hosting, configure `GENFEEDAI_CDN_URL` and, if media is served directly by
it, `GENFEEDAI_MICROSERVICES_FILES_URL` on the MCP server. Only these media origins
are allowed by the widget CSP (the CDN defaults to `https://cdn.genfeed.ai`).
Other HTTP(S) media URLs remain available through an explicit open-link action.
The static HTML resource is public; all account data still comes from authenticated
tool calls. It contains no bearer tokens or account cookies.
