# AI Providers

Genfeed exposes deployed providers through **Organization settings →
Integrations**. Saving a credential validates it against the provider before it
is encrypted for the organization. The catalog also includes prepared direct
media identities; their credential checks do not establish generation readiness.

On Genfeed Cloud, bring-your-own-key is included with Pro, Scale, and
Enterprise: generations that run on an organization key draw no credits and
carry no usage fee. Without a paid plan, stored keys are ignored and generation
falls back to Genfeed-hosted providers billed in credits. Self-hosted
deployments never gate BYOK.

## HeyGen API v3

HeyGen catalog reads, account validation, avatar rendering and status polling use
API v3. Avatar IDs are renderable look IDs from `/v3/avatars/looks`; character
group IDs are separate. Photo animation uses an image input to `/v3/videos`.
The prompt-driven HeyGen Video model uses `/v3/models/videos`.

Catalogs follow provider cursors. Connected organization keys expose their own
private looks and voices alongside public presets. Platform reference catalogs
contain public entries only.

For webhook completion, register the application's
`/v1/webhooks/heygen/callback` URL through `/v3/webhooks/endpoints` and subscribe
to `avatar_video.success` and `avatar_video.fail`. Store HeyGen's returned
signing secret in `HEYGEN_WEBHOOK_SECRET`. The receiver verifies the `signature`
header against the raw body and deduplicates events using their signed video ID
and event type. A failed processing attempt releases its claim so the provider
can retry. Request bodies carry `callback_id` for correlation; they do not send
a per-request callback URL.

See HeyGen's [v3 migration comparison](https://developers.heygen.com/endpoint-version-comparison),
[video request contract](https://developers.heygen.com/reference/create-video)
and [webhook contract](https://developers.heygen.com/docs/webhooks).

These direct identities preserve provider-owned credential boundaries. Replicate
and fal routes retain their own identities, and OpenRouter `x-ai/` names do not
select direct `xai` credentials. The `direct-media` directory also contains an
OpenAI image compiler/client foundation under the existing `openai` identity.

Credential validation uses non-generation provider reads. A valid credential or
compiled request does not admit a model, wire its runtime dispatcher, or establish
funding. Runtime admission and registry wiring, durable account-bound jobs and
uncertain-submission reconciliation, billing/funding, tenant asset admission,
protected output ingestion and saved assets remain application delivery work.
BFL output URLs expire after 10 minutes; Runway output URLs expire within 24–48
hours. The application must persist outputs rather than treating temporary URLs
as saved assets. Aborting local HTTP does not confirm remote cancellation.

Independent review and authorized live image/edit/video
acceptance remain separate gates; neither is established by these foundations.
They do not change defaults or activate a route.

## Configure an organization key

1. Create a restricted credential in the provider dashboard.
2. Open **Organization settings → Integrations**.
3. Expand the provider card and enter the key. Kling AI and Higgsfield also
   require the provider secret.
4. Select **Validate and save**.
5. Confirm that the card reports a connected state before running generation.

Removing a key disables that organization's credential. A self-hosted server
fallback may still be used when the execution adapter supports its corresponding
environment variable.

## Callback-dependent providers

Some asynchronous media providers require a public base URL:

| Provider    | Additional configuration                                             |
| ----------- | -------------------------------------------------------------------- |
| Argil       | `GENFEEDAI_WEBHOOKS_URL`, `ARGIL_WEBHOOK_SECRET`                     |
| HeyGen      | `HEYGEN_WEBHOOK_SECRET` when provider webhooks are enabled           |
| Kling AI    | `GENFEEDAI_WEBHOOKS_URL` for asynchronous completion                 |
| Leonardo.AI | `LEONARDO_WEBHOOK_SECRET`; optionally `LEONARDO_WEBHOOK_ALLOWED_IPS` |
| Replicate   | `GENFEEDAI_WEBHOOKS_URL` for webhook-capable predictions             |

Do not expose webhook secrets to the client application. Configure them only in
the server environment used by the API and workers.

## Verify execution

1. Confirm that the required provider appears connected.
2. Select a model whose provider matches the configured key.
3. Run the smallest non-sensitive generation supported by that model.
4. For asynchronous providers, confirm the provider job ID is recorded and the
   generated asset reaches a terminal state.
5. Review provider usage and Genfeed logs without copying credential values.

For registry behavior and managed-provider boundaries, see
[Provider Registry](/core/provider-registry) and [Models and Providers](/models).


## Crun image and video generation

Crun supports reviewed Nano Banana Pro and Seedream 4.5 image models, Kling 2.5 Turbo Pro videos and Veo 3.1 Fast text-to-video. Deployment
admission is disabled by default. Operators must review the imported contract,
activate the model and configure hosted acquisition pricing before enabling
hosted requests. Crun is unavailable through the managed inference proxy.

Studio requests an exact quote for the prepared prompt and selected controls.
The quote lasts 60 seconds and covers all requested outputs. Changing inputs or
account requires another quote. Explicit prompt enhancement runs before quoting;
quoting does not enhance the prompt automatically. Eligible organization keys
report zero customer credits and retain BYOK usage accounting.

Generation persists task identity before provider creation and copies results
into owned storage. Accepted tasks continue to reconcile after admission is
disabled. Keep the original key available until accepted tasks drain; rotating or
deleting it may require operator recovery. Do not retry provider creation after
an ambiguous response. Seedream reference images require authorized ingredient
records with known file size and dimensions.

Crun video quotes use authenticated `POST /videos/crun-quote`; generation uses
`POST /videos` with the returned `crunQuoteId`. Quotes last 60 seconds and freeze
the exact prepared input. Each output is a separate task, with up to four outputs.
The API can prepare one quote automatically when no quote ID is supplied.

Kling supports 5/10 seconds and optional ordered start/end image frames. End frames
require a start image; frame inputs omit aspect ratio. Veo supports reviewed
8-second 720p, 1080p and 4k output, with translation true by default (false is
preserved). Veo 4/6 seconds, frames, audio toggles, negative prompts and guidance
are unavailable. Crun video generation is asynchronous; wait-for-completion,
callbacks, remix budget approvals and advanced skill/knowledge execution are
unsupported. Enhanced prompts must carry authorized stored provenance.

Provider prices must match a reviewed fixed estimate. Operator approval, explicit
admission enablement and funded canary checks are separate release steps. Stored
video inspection establishes duration, dimensions and audio metadata; temporary
provider URLs are copied into owned storage before financial completion. Accepted
work continues reconciliation when admission is disabled.
