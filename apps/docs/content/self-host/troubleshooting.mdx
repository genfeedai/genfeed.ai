# Troubleshooting

Start by looking at what is running and what it logged:

```bash
docker compose --env-file .env -f compose.yml ps
docker compose --env-file .env -f compose.yml logs genfeed
docker compose --env-file .env -f compose.yml logs postgres
```

## Debian 13: Docker Compose v2

Debian 13 provides Compose v2 in its
[`docker-compose` package](https://packages.debian.org/trixie/docker-compose).
If `docker compose` is missing and you use Debian's Docker packages, install:

```bash
sudo apt-get update
sudo apt-get install docker-compose
docker compose version
```

With Docker CE, install `docker-compose-plugin` from Docker's apt repository
instead. Set up that repository by following Docker's
[Debian install guide](https://docs.docker.com/engine/install/debian/), then:

```bash
sudo apt-get install docker-compose-plugin
docker compose version
```

Genfeed uses the `docker compose` command (with a space). Check the reported
version rather than inferring it from the package or executable name.

## `P1001: Can't reach database server at postgres:5432`

This error means the Genfeed container could not open a connection to the
`postgres` container over the Compose network. Check these in order:

1. Confirm PostgreSQL is running and healthy with the `ps` and `logs postgres`
   commands above.
2. **Container networking.** Genfeed reaches PostgreSQL by the hostname `postgres`
   on the Compose network. Check that both containers are on the same network and
   that you did not override `POSTGRES_HOST` or `DATABASE_URL` with a value that
   does not resolve from inside the container.
3. **Firewall.** A host firewall (for example ufw, firewalld, or custom nftables
   rules) that blocks traffic between containers on Docker's bridge network
   prevents `genfeed` from reaching `postgres`.
4. **`FORWARD` policy.** If the `iptables` or `nftables` `FORWARD` chain policy
   is `DROP` and Docker's own forwarding rules are missing, container traffic is
   dropped:

   ```bash
   sudo iptables -S FORWARD
   ```

   Restart Docker after changing firewall rules so it can recreate its rules, then
   recreate the stack with `docker compose --env-file .env -f compose.yml up -d`.

Rootless Docker and user-namespace setups can also change container networking.
See Docker's
[packet filtering and firewalls](https://docs.docker.com/engine/network/packet-filtering-firewalls/)
documentation.

## A port is already in use

Genfeed publishes `3000`, `3010`, and `3014`. If another program uses one, either
stop it or move Genfeed to different host ports in `.env`:

```env
SELFHOSTED_APP_PORT=3100
SELFHOSTED_API_PORT=3110
SELFHOSTED_MCP_PORT=3114
```

Recreate the stack afterwards. If you change the web or API port, also update
the public URLs; see [Configuration](/self-host/configuration#public-urls).

## `npx @genfeedai/create` fails on Node.js

`@genfeedai/create` requires Node.js `>=24 <25`. Check with `node --version`.
Install Node.js 24, or skip Node entirely and use the
[release bundle](/self-host/installation#option-2-release-bundle-with-docker-compose).
This is separate from `@genfeedai/cli`, which needs Node.js 22.12 or newer.

## Missing provider key

**Symptom:** the first chat, agent run, or draft fails with
`Missing provider key: OPENROUTER_API_KEY`. The API returns HTTP `503` with
`code: "missing_provider_key"`, and agent flows show "AI provider not connected".

**Cause:** text generation routes through OpenRouter, and the key is not set.
`OPENROUTER_API_KEY` starts blank in `.env.example`. An OpenAI or Anthropic
key does not replace it, because those keys only serve `openai/*` and
`anthropic/*` models and branded drafts are OpenRouter-only.

**Fix:**

1. Create a key at [openrouter.ai/keys](https://openrouter.ai/keys) and add
   credits.
2. In `.env`, set `OPENROUTER_API_KEY` to the real key. Or save it per
   organization under **Organization settings → Integrations**.
3. Recreate the stack, because `restart` does not re-read `.env`:

   ```bash
   docker compose --env-file .env -f compose.yml up -d
   ```

4. Run the same generation again. The failed attempt was rejected before any
   work started, so nothing needs cleaning up.

The same message can name `OPENAI_API_KEY` or `ANTHROPIC_API_KEY`: set that key,
or choose a model that routes through OpenRouter. See
[Provider API keys](/self-host/provider-api-keys).

## Generation does nothing or fails

Read the error first. If it says `Missing provider key`, follow the section
above. Otherwise, add the key for the provider behind the model you chose
(Replicate or fal for media, ElevenLabs for voice), recreate the stack, and try a
small request. Self-hosting has no Genfeed credits. Then check the provider's
dashboard for balance and model access, and read the container logs.

If a turn fails with `OPENROUTER_API_KEY is not configured`, set a real
`OPENROUTER_API_KEY` in `.env` and recreate the stack. Text generation and the
agent use OpenRouter, and the install-readiness check reports text generation as
not ready until the key is set. Keys must be real: Settings validates each key
with the provider before saving it (a placeholder shows "Invalid ... API key"),
and a placeholder in `.env` counts as not configured.

The Community image does not start GPU or local-model services, so a model that
needs your own ComfyUI or GPU host will not run unless you point
`DARKROOM_COMFYUI_URL` at one.

## I cannot sign up or sign in

- **No sign-up form, and no login page at all.** If you set
  `BETTER_AUTH_ENABLED=false`, there is no login wall: you are already the seeded
  local user. Nothing to fix.
- **The login page has no email and password form.** It offers Google and Magic
  Link. Magic Link needs `RESEND_API_KEY`; Google needs OAuth credentials.
  Otherwise create the account through the API and sign in at `/login/password`.
  See [Create the first user](/self-host/installation#create-the-first-user).
- **The login wall does not appear after you enabled it.** Set
  `BETTER_AUTH_ENABLED=true` (and, if you set it, `NEXT_PUBLIC_BETTER_AUTH_ENABLED`
  to match), then recreate the stack. A plain restart does not re-read `.env`.
- **Sign-in fails behind a domain.** Set `BETTER_AUTH_URL` to your public API URL
  and `BETTER_AUTH_TRUSTED_ORIGINS` to your public app URL, then recreate the
  stack. See [Reverse proxy and HTTPS](/self-host/reverse-proxy).
- **A new account is empty.** Each signup gets its own organization and brand,
  separate from the seeded `default` workspace.

## I am logged out after a restart

Sessions are signed with `BETTER_AUTH_SECRET`. Left empty, the container
generates one and keeps it in `/data/.better-auth-secret` on the `genfeed_data`
volume. If you are logged out after every restart, that volume is not persisting:
check that you did not run `docker compose down -v`, change the project name, or
remove the volume. If you set `BETTER_AUTH_SECRET` yourself, make sure the value
is identical on every start.

## Back up and reset

Back up both volumes, `postgres_data` and `genfeed_data`. `genfeed_data` holds
`/data/.encryption-key` (or whatever you set as `TOKEN_ENCRYPTION_KEY`). Stored
provider and channel credentials cannot be decrypted without it, so keep a copy
of that key with your database backups.

To start over from a clean state:

```bash
docker compose --env-file .env -f compose.yml down -v
docker compose --env-file .env -f compose.yml up -d
```

`down -v` deletes the database, generated files, and generated secrets. There is
no undo.

## Email is not sending

Magic links, password resets, verification emails, and invites are sent through
Resend. Set `RESEND_API_KEY` (and `RESEND_FROM_EMAIL` for a sender you have
verified with Resend), recreate the stack, and check
`docker compose --env-file .env -f compose.yml logs genfeed` for delivery errors.
Email and password sign-in does not need email unless verification is switched
on.

## The disk is full

Genfeed needs about 10 GB free, and generated media and Docker images grow it.
See where the space went:

```bash
docker system df
docker compose --env-file .env -f compose.yml exec genfeed du -sh /data/files
```

Remove unused images with `docker image prune` after an upgrade. Do not run
`docker volume prune` unless you have a backup, because it removes the volumes
of stopped stacks.

## Apple Silicon

The image is `linux/amd64`. On Apple Silicon, Docker Desktop runs it under
emulation, which is slower to start and to run. If the container exits at once or
the health check keeps failing, give Docker Desktop more CPU and memory in its
settings, and allow extra time on first start.

## The web UI loads but nothing works behind my domain

The published image defaults its browser-facing settings to `localhost`. Set the
public URL variables described in
[Reverse proxy and HTTPS](/self-host/reverse-proxy), recreate the stack, and
confirm in your browser's network tools that requests go to your API address.

## MCP returns 401

Turning off the login wall does not turn off MCP authentication. Register the
client as described in [MCP server](/api-reference/mcp#connect-to-your-instance),
or use a scoped API key.

## The health check passes but something is broken

`curl http://localhost:3010/v1/health` reports only that the API process
responds. It does not test the database, queues, providers, or workflows. Use
the logs to look further.

## Reporting a problem

Use the [bug report form](https://github.com/genfeedai/genfeed.ai/issues/new/choose)
for reproducible defects, and include your release version and the relevant log
lines, with secrets removed. The public tracker does not provide a support SLA.
Report suspected vulnerabilities through the
[security policy](https://github.com/genfeedai/genfeed.ai/security/policy), not a
public issue.
