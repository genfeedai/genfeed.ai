**New**
- Reverse engineer a reference: in a storyboard plan, "..." then "Reverse a video" (a Library video up to 60 s) turns its takes into shots with timed cuts, camera moves, sound and a prompt per shot, and "Reverse an image" adds its look as the style and one shot that recreates it. The storyboard agent tool has the same `reverse` action. Cut times are estimates read from sampled frames.
- Every place that asks which account to post to shows the same avatar row, the profile picture with its platform badge: the agent publish and schedule cards, the platform pickers that used to show text only, and the Filters menus.
- Channel logos sit on square tiles, so the connected accounts on MCP channel cards line up.
- Operator alerts (trend ingestion health, Apify budget) go to their own Discord Alerts channel instead of the posts channel. Set the channel ID in Admin > Platform settings > Notifications; until then those alerts are skipped.
- Emails show a video as its first frame with a play button, and the card title stays on one line.
- MCP `upload_media` takes a `brandId`, so an upload lands in the brand you name. An organization with several brands must name one.

**Better**
- Pickers in the prompt bar (folder, quality, resolution, aspect ratio, outputs, avatar, voice, duration, preset, brand voice, elements) and the scope and status pickers share one select with an icon per option and a search field.
- Credit pack tiles name their credits.
- Dates in the app, the extension and agent cards read the same short date everywhere.

**Fixed**
- An organization that was given admin credits is no longer held back by the free trial, so it can generate right away.
- Switching organization is handled in one place, and the provisional state while an organization is confirmed no longer leaks into requests.
- Reverse, mirror and text overlay on a video queue their completion event like resize, so an API restart no longer leaves the video processing.

**Steadier**
- The API logs one JSON line per entry in production and records an "Event loop blocked" warning with the blocking code, to find the cause of the short request stalls. This is a diagnosis and a mitigation, not a proven fix.
- The app stops error replay recording and reports DOM growth when a tab passes 768 MiB, to find the approvals page crash. Also a mitigation, not a proven fix.
