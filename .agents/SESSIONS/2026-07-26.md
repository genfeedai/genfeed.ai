### Session 3 — item 2 shipped

**Module-owned nav column.** `SidebarNavPanel` (`packages/props/navigation/menu.props.ts`) is the
seam: a module hands the shell a panel, the shell swaps that body in for the surface's menu items
and keeps everything around it — logo, section label, org switcher, user profile. The sidebar never
learns what the panel renders.

The two hard-wired conversation returns are gone. `if (isUniversalWorkspaceShell) return
conversationSidebar` was the old model in one line: **every** protected route — Studio, Library,
Workflows, admin — surrendered its nav column to the agent thread list. The conversation is now one
entry in the surface list like any other module, and `AgentSidebarContent` is constructed in
`app-protected-layout.tsx` rather than reached for inside the sidebar.

Consequence worth stating plainly: the thread list no longer appears on non-agent routes. It is
reachable from `/agent`, and the *active* conversation still follows the user everywhere via the
inspector rail from item 1. Those two are different objects and the old shell conflated them.

Tests inverted accordingly — five in `app-protected-layout.test.tsx` asserted the conversation
sidebar on Studio/Workflows/admin/workspace routes and now assert each module's own nav, plus a new
direct-render test that a `navPanel` overrides a surface's items while the surface keeps its identity.

### Session 3 — item 3 shipped

**The frame stopped waiting for the shell.** `isWorkspaceShellReady` (`isUniversalWorkspaceShell &&
agentApiService !== null`) decided far more than whether the shell body could mount: whether the
sidebar existed, whether the topbar existed, whether an error boundary wrapped the tree, whether
thread commands reached the palette. All of that is route business. Renamed to
`isWorkspaceShellMounted` and reduced to two consumers — the mount telemetry and AppLayout's
`data-workspace-shell` attribute.

What changes in practice:

- **Canvas routes keep their chrome while the shell boots.** The old guard read `!ready && (editor
  canvas || moodboard || onboarding)`, so those surfaces lost sidebar *and* topbar for the whole
  pre-auth window and got them back on boot. Now only `isFocusedOnboardingRoute` suppresses chrome.
- **Focused onboarding is actually focused.** `/agent/onboarding` is a registered shell route, so
  `ready` was true there and it rendered full chrome in production — the test that claimed otherwise
  passed only because its mock pathname (`/agent/onboarding`, no org segment) missed the registry.
  Test now uses the org-scoped path.
- **The error boundary is unconditional.** It wrapped only the ready case, so a render failure on an
  unregistered route escaped to the root. Message is `Protected shell render failed`, not
  `Conversation shell…`.
- **`AppLayout` stopped calling the sidebar "Conversation threads."** That aria-label branched on
  `isWorkspaceShell` and, after item 2, mislabels every module's own nav column. Always `Navigation`.
- Thread commands now reach the palette on every surface but onboarding — the conversation is
  reachable everywhere, so its threads should be too.

New test holds the line: auth held un-loaded on `/editor/new` asserts the sidebar and topbar survive
while `universal-workspace-shell` is absent.

### Session 3 — item 4 shipped

**ADR v2.0.0 → v3.0.0.** `ADR-CONVERSATION-SHELL-CONTRACTS` described the model the last three
commits inverted: conversation as one of three top-level shell states, `?thread=` as a reserved key
on every non-agent protected URL, and the shell deciding whether a product surface got to render.

What v3 rewrites:

- **Invariant 1** — top-level state is `canvas | overlay`. Added invariants 11–13: the frame is
  route-decided and never readiness-decided; one mounted conversation owns the single composer; the
  nav column belongs to the module that owns the surface.
- **`thread` withdrawn from the reserved query keys.** Thread identity has two sources — the
  `/agent/:id` path segment and the agent store. The resolver strips the key and canonicalizes by
  `replace`, so old links still land on the surface they name.
- **State/history matrix** — conversation rows became "conversation route" (a canvas whose surface
  is the conversation; it appears in the From/To column because the *route* changes, not the state).
  Two new rows: a URL carrying the withdrawn key, and inspector open/close/resize as ephemeral chrome.
- **Three new sections** — Conversation Surface Contract (thread list vs active thread as different
  objects; single-composer ownership order; collapse-is-not-unmount; one row of cards, never an
  embedded surface), Nav Column Ownership, Permanent Frame Contract.
- **Route mode `conversation` is now documented as classification, not renderer selection** — which
  is exactly what the type comment in `workspace-shell.interface.ts` says.

Parity denominator untouched: 206 stays valid, since demoting the conversation removes no route.
`MEMORY.md`'s one-line index entry updated to match.
